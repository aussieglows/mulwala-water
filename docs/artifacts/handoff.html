Do this first — get the code + env. Push any local commits from the old computer (git push origin rebuild). Then on the new computer: git clone https://github.com/aussieglows/mulwala-water → git checkout rebuild → npm install → pull env from Vercel (below) → npm run dev (port 3000).
Environment — pull from Vercel, never transfer .env. The .env file is not moved between machines. Instead: npm i -g vercel → vercel login → vercel link (pick mulwala-water) → vercel env pull .env.local. That writes DATABASE_URL (Neon) and the rest into .env.local, which Next.js reads automatically. Manual fallback: Vercel → project mulwala-water → Settings → Environment Variables → reveal DATABASE_URL and paste it into .env.local. That one var powers the homepage portfolio logos + /admin; public pages render without it.

A full rebuild of mulwalawater.com — the site for Mulwala Water Operating & Investment LLC, a firm that advises, operates, and invests in founder-led, family-owned, sponsor-backed and multi-unit businesses. Laura (laura@aussieglows.com) manages it for her husband. One Next.js project: the public marketing site is the rebuild; /admin is an accounting/CMS section that is untouched — leave it alone.

3. Stack & conventions

  • Next 16 App Router, React 19, TypeScript, Tailwind v4 (CSS-var tokens in app/globals.css).
  • Copy lives in typed content/*.ts modules, not inline JSX. Components in components/site/, pages in app/(public)/.
  • The truss-bridge motif (components/site/Truss.tsx) is the single graphic system.
  • Verify: tsc --noEmit then next build. If stale .next/types errors after moving routes, delete .next and rebuild.
